# ADR 003: Dynamic Plugin Loading via C FFI and `libloading`

## Status

Accepted

## Context

The GUI plugin host originally compiled every analysis plugin directly into `augur-gui`. That forced plugin authors to edit the GUI crate and rebuild the whole application for every change. Plugins evolve independently from the recorder, so a runtime loading mechanism is needed.

## Decision

Use a small hand-rolled C ABI plus `libloading` for runtime plugin discovery and execution.

The new boundary is defined in `augur-plugin-api` and includes:

- zero-copy frame access through borrowed FFI slices
- host callbacks for overlays and warnings
- a string-keyed JSON context bus for inter-plugin data
- declarative settings and status schemas instead of direct `egui` calls
- an exported panic-safe vtable generated by `export_plugin!`
- explicit `vtable_size` and `abi_version` guards so stale plugins are rejected before any host
  function-pointer call
- plugin implementations live outside `augur-rs`; host-owned analysis features
  stay in `augur-gui` instead of pretending to be plugins

## Consequences

### Positive

- Plugin authors can rebuild and reload plugins without recompiling `augur-gui`
- The host/runtime contract is explicit and lives in a standalone crate
- `augur-core` stays free of application-specific logic
- Load failures become recoverable UI-visible errors instead of build-time coupling
- Host upgrades can reject stale same-size plugin dylibs cleanly instead of risking startup crashes

### Negative

- The FFI boundary requires explicit serialization and ABI discipline
- Dynamic libraries add platform-specific packaging and loader concerns
- Plugin UI is limited to the declarative schema supported by the host

## Alternatives Considered

### Keep Compile-Time Registration

Rejected because it keeps `augur-gui` as the compilation bottleneck and discourages independent plugin iteration.

### Use a Heavier Stable-ABI Framework

Rejected because the plugin API surface is small enough that a handwritten FFI layer is simpler, easier to audit, and introduces fewer dependencies.
